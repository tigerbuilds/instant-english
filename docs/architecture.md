# Architecture

- 作成日: 2026-10-11
- ステータス: Accepted（Phase 2 完了時点）
- 対象: MVP

このドキュメントは、Phase 1 で決めた技術がどうつながり、各部品が何を担当するかを定義する。要件は `product-requirements.md`、技術選定の理由は `decisions/` を参照。

## 1. 全体図

```text
┌─────────────────────────────────────────────────────┐
│ Windows PC                                           │
│                                                      │
│  ┌────────────────┐   HTTP    ┌─────────────────┐   │
│  │ ブラウザ        │ ───────▶ │ Backend          │   │
│  │ React + Vite   │ ◀─────── │ Node.js + Express│   │
│  │ (frontend/)    │   JSON    │ (backend/)       │   │
│  └────────────────┘           └───────┬─────────┘   │
│                                       │ HTTP         │
│                                  読む  │              │
│                       ┌──────────┐    ▼              │
│                       │ 問題文    │  ┌─────────────┐  │
│                       │ ファイル  │  │ Ollama       │  │
│                       └──────────┘  │ localhost:11434│
│                                     │   └ Local LLM │  │
│                                     └─────────────┘  │
└─────────────────────────────────────────────────────┘
```

- すべて 1 台の PC 上で動く。インターネット通信は無い。
- 部品は 4 つ。ブラウザ（画面）、Backend、問題文ファイル、Ollama。
- 部品どうしは HTTP でつながる。渡すデータは JSON。

---

## 2. 各部品の責務

### ブラウザ（frontend/）

React + Vite + TypeScript。ユーザーが直接触る部分。

担当すること:

- 問題文の表示
- 制限時間のカウントダウンと自動送信
- 英文の入力と送信
- 評価結果の表示（ユーザーの英文と「より自然な英文」を並べる）
- 「次へ」の操作
- 評価待ちの表示

担当しないこと:

- 問題文の保持（Backend に 1 件ずつ取りに行く）
- LLM への指示文（プロンプト）
- Ollama との通信

### Backend（backend/）

Node.js + Express + TypeScript。画面と LLM の間に立つ。

担当すること:

- 問題文ファイルを読み、1 件ずつ返す
- ユーザーの英文を受け取り、問題番号から日本語の原文を引く
- プロンプトを組み立てて Ollama に送る
- Ollama の返事を確かめ、決まった形に整えて画面に返す
- 制限時間などの設定値を保持する

担当しないこと:

- 画面の描画
- LLM の計算そのもの

### 問題文ファイル

開発者が書いた日本語の文の一覧。コードを変えずに追加・編集できる形式で置く（FR-1.2）。形式は Phase 5 で決める。

### Ollama

ローカル LLM の実行環境。`localhost:11434` で HTTP を待ち受ける。プロンプトを受け取り、文章を返す。中身は llama.cpp（ADR 003）。

## 3. データの流れ

### 3.1 問題文を表示する

```text
問題文ファイル → Backend : ファイルの中身（日本語の文の一覧）
Backend → ブラウザ       : 問題 1 件（番号と日本語）
ブラウザ → ユーザー      : 画面に描いた日本語
```

Backend が返すものの例:

```json
{ "id": 3, "japanese": "昨日の会議、ちょっと長かったよね" }
```

1 件ずつ返す理由: 将来 Database に移しても、画面側を変えずに済む。

### 3.2 英文を評価する

```text
ブラウザ → Backend : 問題番号 と ユーザーの英文
Backend → Ollama   : プロンプト（指示文 + 日本語の原文 + ユーザーの英文）
Ollama → Backend   : LLM が書いた文章
Backend → ブラウザ : 評価結果（決まった形の JSON）
```

ブラウザが送るものの例:

```json
{ "questionId": 3, "answer": "Yesterday's meeting was a little long, wasn't it?" }
```

Backend が Ollama に送るプロンプトの骨子:

```text
あなたは英会話の講師です。
日本語: 昨日の会議、ちょっと長かったよね
学習者の英訳: Yesterday's meeting was a little long, wasn't it?
文法の指摘、自然さの指摘、より自然な英文を、次の JSON 形式で返してください。
{ "grammar": "...", "naturalness": "...", "better": "..." }
```

Backend がブラウザに返すものの例:

```json
{
  "grammar": "問題ありません。",
  "naturalness": "wasn't it? は少し硬い印象です。",
  "better": "That meeting yesterday ran a bit long, huh?"
}
```

Ollama の返事はただの文章であり、頼んだ形で返らないことがある。Backend はそれを確かめ、崩れていれば直すかエラーとして扱う。そのうえで画面に渡す。

空欄で送信された場合（FR-3.5）は、指摘を省き `better` だけを返す。

---

## 4. なぜブラウザが Ollama を直接呼ばないのか

技術的には可能だが、Backend を挟む。理由:

1. **プロンプトの置き場所**。ブラウザで動くコードは誰でも読める。プロンプトを裏側に置けば、画面に触らず改善できる。
2. **将来の拡張**。Database を足すとき、「受け取り、評価し、保存する」処理は 1 か所にまとまっていてほしい。
3. **変わりやすいものを閉じ込める**。Ollama を知っているのは Backend だけにしておくと、将来 LLM の実行方法を替えても画面は変わらない。
4. **返事の検証**。LLM の返事は形が崩れることがある。確かめて整える場所が要る。

---

## 5. 起動時に動くもの

MVP では 3 つのプログラムを立ち上げる。

| プログラム | 役割 | 待ち受け |
|---|---|---|
| Vite の開発サーバー | 画面のコードをブラウザに配る | localhost:5173（既定） |
| Backend | API | localhost:3000（予定） |
| Ollama | LLM | localhost:11434 |

ポート番号は Phase 4 で実際に動かして確認する。

---

## 6. MVP 後の変更点（見込み）

- Database 導入時: 問題文ファイルと回答の保存先が Database に変わる。変わるのは Backend の中だけで、ブラウザとの JSON は変えない。
- 画面の記録表示（US-8）: Backend に「記録を返す」API が増える。
