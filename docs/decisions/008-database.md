# ADR 008: Database

- 日付: 2026-10-24
- ステータス: Accepted

## Context

MVP は「何も記憶しないアプリ」として完成した（Phase 8）。次に、回答の記録を残し、累計問題数と継続日数（US-8）を出す。将来の「指摘が付いた回答の復習」（将来の拡張候補 3 番）も同じ記録から賄う。

保存するのは事実だけとし、集計（累計、継続日数、最新利用日）は保存せず、その都度計算する。真実の置き場を 2 つにしないため。

実行環境は 1 人、ローカル PC、件数は多くても数千件（NFR-2）。費用 0 円（NFR-1）。

## Options

| | PostgreSQL | SQLite |
|---|---|---|
| 正体 | 別プログラムとして常駐するサーバー。裏側が接続しに行く | ファイル 1 つ。裏側のプログラムに組み込まれて動く |
| 導入 | インストールと初期設定。常駐プログラムが 1 つ増える（Ollama、裏側、画面に続く 4 つ目） | 不要。Node.js 24 の標準モジュール `node:sqlite` で使える |
| このアプリとの相性 | 1 人・ローカル・数千件には過剰 | 適合 |
| 実務での利用度 | Web サービスの裏側で最も一般的 | 組み込み、モバイル、小規模ツールで一般的 |
| 学べること | 接続、ユーザーと権限、サーバーとしての運用。クラウド公開時に使うものと同じ | SQL そのものは同じ。運用面は学べない |
| 費用 | 0 円（OSS） | 0 円（パブリックドメイン） |

Docker の要否（ADR 004 で「Database 導入時に再検討」とした）は、SQLite では入れるものが無いため検討対象から外れる。

## Decision

**SQLite** を採用する。Node.js 24 標準の `node:sqlite` モジュールを使い、ライブラリは追加しない。

Database のファイルは `backend/data/` に置き、Git には入れない（実データは公開しない方針、product-requirements.md 6 章）。

## Why

- 今はローカルで 1 人で使う段階であり、SQLite で過不足がない。「必要以上に高度なものを入れない」方針の適用。
- 常駐プログラムを増やさない。起動手順が今のまま（Ollama、裏側、画面の 3 つ）で済む。
- `node:sqlite` が標準で入っており、ネイティブビルドの要る外部ライブラリ（`better-sqlite3` など）も不要。
- SQL の文法、Table、Primary Key、Foreign Key、JOIN、Index といった学びたい項目（要件定義の 9 章）は SQLite で全部扱える。

## Trade-offs

- PostgreSQL でしか得られない経験（サーバーへの接続、権限、運用、クラウドの Database hosting）は後回しになる。クラウド公開（Phase 13）を本気でやる段階で PostgreSQL への移行を検討する。
- `node:sqlite` は Node.js の比較的新しい機能で、API が将来変わる可能性がある。変わったときは裏側の Database を扱う部分だけ直す。
- SQLite は同時書き込みに弱いが、1 人で使う限り問題にならない。

## 移行を容易にするための方針

- SQL は標準的な書き方に寄せ、SQLite 固有の機能に依存しない。
- Database を扱うコードは 1 つのファイル（`backend/db.ts`）に閉じ込め、他の部分は「問題を取る」「回答を保存する」といった関数だけを呼ぶ。Ollama を `ollama.ts` に閉じ込めたのと同じ考え方。
