# ADR 005: Git / GitHub の運用

- 日付: 2026-10-07
- ステータス: Accepted

## Context

このプロジェクトは GitHub ポートフォリオを目的の一つとしており、「要件定義 → 技術選定 → 設計 → 実装 → テスト → 改善」の過程を Git 履歴で示したい。1 人開発だが、Pull Request の流れを学ぶ目的もある。公開範囲、ブランチ運用、Commit メッセージ規約、秘密情報の扱いを決める。

前提:

- 開発者は Git の基本操作に慣れている。
- GitHub CLI（gh）が導入済みでログイン済み。
- 現時点では API Key などの秘密情報は無い（Ollama はローカルで認証不要）。

## Options

### 公開範囲

| | 最初から Public | Private で始めて後で Public |
|---|---|---|
| 試行錯誤の履歴 | すべて見える。「過程を見せる」目的には利点 | 整ってから公開できる |
| 心理的負担 | 誤りも見える | 低い |
| 機能 | ブランチ保護が無料で使える | ブランチ保護は Private では有料プランが必要 |

### ブランチ運用

| | すべて `main` 直接 | すべて PR | 文書は `main` 直接、コードは PR |
|---|---|---|---|
| 学習価値 | PR を学べない | 高い | 高い |
| 手間 | 最小 | 文書 1 行の修正にも PR が要る | 中間 |

### Commit メッセージ

Conventional Commits（`feat:` `fix:` `docs:` `chore:` `refactor:` `test:` の接頭辞）。変更の種類が一目で分かり、広く使われている。

## Decision

- 公開範囲: **最初から Public**。
- ブランチ運用: **文書だけの変更は `main` に直接 Commit。コードを書く Phase 4 以降は、Phase または Step ごとにブランチを切り、PR を作って `main` に取り込む**。承認者はいないが、PR の説明文に「何を・なぜ」を書き、差分を見返すことを目的とする。
- Commit メッセージ: **Conventional Commits** を使う。
- 秘密情報: 現時点では無い。`.gitignore` には `node_modules` などの生成物のみ入れる。環境変数の仕組みは必要になった時点で導入する。
- GitHub リポジトリの作成: Phase 3 で `.gitignore`、`.gitattributes`、README を揃えてから行う。
- `main` ブランチの保護（PR 経由のみ、force push 禁止）を Phase 3 で設定する。

## Why

- 「過程を見せる」ことが目的なので、試行錯誤が見えることは欠点ではなく利点。
- Public ならブランチ保護が無料で使える。
- 文書の変更まで PR にすると手間が学習の邪魔になる。コードの変更に PR を限定することで、PR の価値（差分の見直し、説明文の習慣）に集中できる。

## Trade-offs

- Public のため、誤った Commit もすべて公開される。履歴の書き換えはしない方針なので、誤りは次の Commit で直す。
- 1 人開発の PR は形式的になりやすい。説明文を書く習慣を保てるかは本人次第。

## 他人からの PR について

- GitHub では、他人はリポジトリに push できない。書き込めるのは所有者と招待された人のみ。
- 他人は Fork を経由して PR を提案できるが、取り込むかどうかは所有者が決める。提案が来てもコードは変わらない。
- 学習用の個人リポジトリに見知らぬ人から PR が来ることは現実にはほぼ無い。Issue の受付は必要なら設定で無効化できる。
