# ADR 007: LLM のモデル選定

- 日付: 2026-10-22
- ステータス: Accepted

## Context

ADR 003 で Ollama を採用し、モデルは Phase 8 で実測して決めるとした。実行環境は CPU 推論（専用 GPU なし）、メモリ 16 GB、LLM に割ける実質 8 GB 前後（NFR-2）。目標は評価 1 回 15 秒以内（NFR-3）。

評価の内容は「文法の指摘」「自然さの指摘」「より自然な英文」の 3 点で、合計 100 語前後の JSON を返させる。

## Options

2026 年 10 月時点の Ollama ライブラリで、CPU 向けに現実的な候補。

| | Qwen3.5 4B | Gemma 4 E4B | Qwen3.5 9B / Gemma 4 12B |
|---|---|---|---|
| 作り手 | Alibaba | Google DeepMind | 同左 |
| ダウンロード | 3.3 GB | 6.6〜9.5 GB | 6.6〜8.0 GB |
| ライセンス | Apache 2.0（`ollama show --license` で確認） | Gemma 利用規約。OSS ではないが無料 | 同左 |
| メモリ予算（8 GB）に対して | 余裕 | 収まる | ぎりぎり |
| 費用 | 0 円 | 0 円 | 0 円 |

## Decision

**`qwen3.5:4b`** を採用する。

- `think: false` で「考えてから答える」モードを切る。CPU では時間を食うため。
- `format` に JSON Schema を渡し、返事を `Evaluation` の形に縛る。
- Gemma 4 E4B との比較は保留。必要になったら Phase 11 以降で行う（`gemma4:latest` は導入済みで、`OLLAMA_MODEL` を変えるだけで試せる）。

## Why

### 実測値（Step 2、`/api/chat` を curl で直接）

| | 1 回目 | 2 回目 |
|---|---|---|
| 全体 | 10.8 秒 | 3.0 秒 |
| モデルの読み込み | 5.1 秒 | ほぼ 0 |
| プロンプトの読み取り | 2.7 秒 | 0.1 秒（同じ system プロンプトは再利用される） |
| 返事の生成 | 2.7 秒で 38 語 | 2.6 秒で 37 語 |

- 生成は 1 秒あたり約 14 語。指摘が 2 つ入って 100 語前後になっても 7 秒程度で、NFR-3 の 15 秒に余裕がある。
- 1 回目の読み込みはアプリ使用中には発生しない（Ollama がモデルを保持する）。
- 返事の質は、`"Yesterday's meeting was a little long, wasn't it?"` に対して `"Yesterday's meeting dragged on a bit, didn't it?"` を返し、口語化の方向が正しい。引用符の揺れなど小さなモデル特有のぶれはある。
- ライセンスが Apache 2.0 で制約が最も少ない。

### 9B 以上を選ばない理由

生成速度がほぼ半分になり、15 秒に近づく。メモリ予算もぎりぎりで、他のアプリに影響する。MVP の目的は「まず出す → すぐ判定 → 次へ」のリズムであり、質より速さを優先する。

## Trade-offs

- 4B クラスは指摘の精度が粗いことがある。中上級ユーザーが自分で判断できる前提（product-requirements.md のリスク参照）。
- Qwen 系は中国の政治的話題で出力に偏りがあるとされるが、このアプリの用途には関係しない。
- モデル名は環境変数 `OLLAMA_MODEL` で差し替えられるようにし、本 ADR の判断を変えやすくしておく。

## セキュリティ上の確認

- モデルは数値データであり通信も実行もしない。入力は PC の外に出ない（ADR 003）。
- Ollama の公式ライブラリから取得した。
